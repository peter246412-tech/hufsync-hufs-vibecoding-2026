# 설계 변화와 피드백 반영

HUFSync는 한 번에 정해진 아이디어가 아니라, 초기 기획·팀원의 수정안·교수 피드백·실제 팀플 경험을 함께 검토하며 발전한 설계입니다. 아래는 그 판단 과정을 정리한 기록입니다. 단계별 날짜와 개인별 세부 기여는 제공 자료에서 확정하지 않아 구분하지 않았습니다.

## 1. 참여 점수에서 논의 상태로

| 검토 단계 | 접근 | 검토하며 발견한 점 |
| --- | --- | --- |
| 초기 구상 | 발언 유형 가중치와 RQI, 지니계수로 개입 시점·대상 판단 | 발언량·표현 품질이 실제 기여와 다를 수 있음 |
| 중간 수정 | 명확성 점수를 제외하고 발화 원문 기준의 관련성·정보성 고려 | 언어별 모델 차이와 ‘낮은 점수 = 지원 필요’라는 가정이 남음 |
| 논의 중심 설계 | 주제·선택지·미해결 질문·결정 상태를 추적하고 개인 의견 준비 지원 | 특정 학생을 판정하지 않고 필요한 맥락을 제공하는 방향 |
| 최신 기획안 | 논의·결정을 업무 조건, 진행 상태, 결과물 기록과 연결 | 의견 전달 이후의 작업 이해와 재작업 문제까지 포함 |

초기에는 `w × R × C × I`와 같은 발언 점수를 검토했습니다. 그러나 명확성을 번역문에서 평가하면 언어 능력이나 번역 오류가 점수에 섞일 수 있습니다. 원문으로 평가하거나 명확성을 빼는 수정도, 모델이 모든 언어와 상황을 동일하게 평가한다는 검증을 대신하지는 못합니다.

최신 기획안은 사람의 발언을 채점해 지원 대상을 정하는 구조를 사용하지 않습니다. 새 주제·미해결 질문이 등록됐을 때 설정에 따른 안내를 제공하고, 사용자가 직접 맥락 설명과 의견 작성을 요청하는 방향입니다.

## 2. 교수 피드백을 통해 점검한 문제

피드백은 제공된 이메일 이미지의 요지를 재구성했습니다. 이메일 원문·연락처·서명은 공개하지 않습니다.

| 점검 내용 | 설계에 반영한 방향 |
| --- | --- |
| 번역된 문장의 명확성을 기여도에 반영할 때 생기는 불이익 | 개인 발언 점수에 따른 개입에서 논의 사건 중심 안내로 이동 |
| 조장에게 특정 학생이 소외됐다고 알려주는 문제 | 개인 질문·초안을 보호하고 공유 논의·업무 상태 중심으로 진행 지원 |
| 3주 안에 구현과 통계적 효과 입증을 모두 약속하는 문제 | 가상 대화 점검과 1~2개 팀 사용성 파일럿을 계획 |
| 캠퍼스·학위과정·연수과정이 섞인 대학 순위 비교 | 같은 범위의 서울캠퍼스 학부 재학생·학위과정 외국인 수를 사용 |
| 숫자 표기와 선행연구 인용의 정확성 | 범위 표기 정리, 논문의 개입 방식·사후 평가를 구분해 기술 |

교수 피드백은 설계 판단의 출발점이며, 특정 기술을 전부 삭제하라는 요구로 해석하지 않았습니다. 검증 부담과 사용 목적을 고려해 초기 구현 범위를 선택했습니다.

## 3. ‘말할 기회’ 이후에 발견한 업무 이해의 차이

최신 기획안에서는 실제 경험의 해석이 한 단계 더 확장됐습니다. 결과물을 많이 수정해야 했던 이유를 단순한 언어 부족으로 보는 대신, 작업을 맡길 때 목적·범위·결과물 기준을 충분히 맞추지 못했던 점에 주목했습니다.

이 변화가 AI Task Alignment의 배경입니다. ‘중국 기업 조사’라는 업무 제목만 남기는 대신, 앞서 정한 비교 대상과 기준을 연결하고 누락된 담당자·결과물·기한을 확인하도록 했습니다.

Contribution도 이 흐름에서 나온 기록 기능입니다. 말의 양을 기여도로 추정하기보다, 사용자가 등록한 작업·결과물과 팀이 확인한 반영 내역을 이어 보려는 구상입니다.

## 4. 정량 지표를 어떻게 다룰 것인가

검토 과정에서는 지니계수를 발언 분포의 보조 지표로만 남기는 방안도 논의했습니다. 다만 최신 기획안의 핵심 기능과 검증 항목에는 지니계수를 넣지 않았습니다. 이후 실제 데이터와 평가 목적이 정해지면 보조 지표의 필요성을 다시 판단할 수 있습니다.

발언이 균등해졌다는 이유만으로 좋은 협업이라고 판단할 수는 없습니다. 현재 계획은 논의 이해, 의견 준비 부담, 업무 이해, 재설명·수정 부담, AI 정보의 정확성을 중심으로 사용성을 확인하는 것입니다.

## 5. 아직 확인해야 할 질문

- 별도 웹앱에 접속하는 수고보다 맥락 설명·업무 정렬의 이점이 큰가?
- AI가 새 질문과 이미 나온 질문을 안정적으로 구분할 수 있는가?
- 업무 조건 확인이 도움이 되는가, 입력 절차만 늘리는가?
- 알림과 개인 지원이 사용자에게 부담스럽지 않은가?
- Contribution 요약이 등록된 작업과 실제 반영 내역을 정확히 나타내는가?

기획 단계의 가정은 이후 구현·사용자 테스트에서 확인하고, 예상과 다른 결과도 변경 기록에 남길 계획입니다.
