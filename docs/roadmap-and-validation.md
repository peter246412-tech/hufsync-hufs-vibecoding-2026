# 개발 범위와 검증 계획

2026-11-11 기준 **본선 진출 시의 개발 계획**입니다. 아래 일정·목표·모집 규모는 완료된 구현이나 검증 결과가 아닙니다.

## 1. 대회 맥락

공식 공지의 1차 평가는 한국외대 현안 관련성 40점, 독창성·창의성 30점, AI 활용성 30점입니다. 2차는 구현 완성도·실현 가능성 30점, 학내 적용 가능성 30점, 파급효과 25점, 발표 전달 15점으로 안내되어 있습니다. [대회 공식 공지](https://contest.hufs.ac.kr/)

이 프로젝트에서는 구체적인 내·외국인 팀플 경험, 대상에 맞는 기능 연결, 실제 시연할 수 있는 범위, 교내 파일럿 가능성을 중심으로 기획을 정리했습니다.

## 2. 기획안의 3주 일정

| 기간 | 계획 | 완료 목표 |
| --- | --- | --- |
| 11.16~11.22 | Next.js 화면, Supabase 인증·채팅방·초대, 한·영·중 메시지·번역, 질문·업무 데이터 구조 | 팀원 4명이 같은 채팅방에서 대화 |
| 11.23~11.29 | AI 토론 카드, 근거 연결, 개인 설명·추가 질문·의견 작성, 업무 요청 추출과 기본 카드 | 논의 상황과 업무 요청을 확인하고 개인 의견을 준비 |
| 11.30~12.06 | 번역 확인·공유, 질문 상태, 업무 조건 확인·승인, 진행·결과물 링크, 기록 요약, 선택형 안내, 권한·정확성 점검 | 전체 흐름의 통합 시연과 소규모 파일럿 |

공식 개발 기간은 2026년 11월 16일~12월 6일입니다. 실제 진행 단계와 날짜가 달라지면 구현 기록에서 갱신합니다.

## 3. 구현 우선순위

| 우선 범위 | 후속 검토 |
| --- | --- |
| 실시간 다국어 채팅, 토론 카드, 근거 연결 | 조장용 고급 진행 안내 |
| 비공개 설명·초안·번역 미리보기·공유 승인 | 외부 협업 도구 자동 연동 |
| 질문별 의견과 결정 기록 | 실시간 음성 인식·화자 분리 |
| 업무 조건 확인, 기본 상태·결과물 링크 | GitHub 커밋·PR 자동 수집, 코드 충돌 관리 |
| 등록된 작업 중심의 기본 기록 요약 | 과제 유형별 고급 협업 기능 |

MVP는 ‘논의 이해 → 의견 공유 → 업무 이해 → 결과물 검토’의 연결을 우선합니다. 공유·승인 흐름을 일찍 연결해 마지막 주 통합 부담을 줄이는 것은 구현 시 검토할 진행 방식입니다.

## 4. 역할 분담 계획

4명이 서비스 기획·사용성 검증, 프론트엔드·UI/UX, 백엔드·데이터·권한, AI API·프롬프트를 중심으로 분담할 계획입니다. 개인별 상세 담당은 실제 역량과 작업에 맞춰 확정하고, 통합 테스트는 함께 수행합니다.

## 5. 가상 대화 검증

한·영·중이 섞인 대화를 직접 작성하고, 프롬프트 조정 예시와 점검 예시를 구분합니다.

| 상황 | 확인할 오류 |
| --- | --- |
| 새 질문과 기존 질문의 반복 | 질문 누락·중복 등록·잘못된 병합 |
| 주제 변경과 복수 제안 | 제안을 확정된 결정으로 바꾸는 오류 |
| 모호한 업무 요청 | 담당자·범위·기한을 임의로 생성하는 오류 |
| 이전 결정과 다른 요청 | 서로 다른 기준을 자동으로 합치는 오류 |
| 결과물 등록과 반영 기록 | 없는 검토·활용 내역을 추가하는 오류 |
| 같은 의미의 다국어 표현 | 언어에 따라 중요한 의미가 달라지는 오류 |
| 채팅 속 시스템 변경 명령 | 분석 자료가 시스템 명령처럼 처리되는 오류 |

기대 출력과 AI 결과를 대조하고 근거 메시지를 확인합니다. 실제 메시지 ID를 참조하더라도 그 내용이 추출 결과를 지지하는지 추가로 점검합니다.

## 6. 소규모 사용자 파일럿

**목표:** 내·외국인 혼합 1~2개 팀, 약 4~8명. 기존 메신저와 번역·AI 도구를 함께 쓰는 방식과 HUFSync를 비교할 계획입니다.

| 항목 | 점검 방법 |
| --- | --- |
| 토론 이해 | 현재 주제·의견·미해결 질문에 대한 설명 확인 |
| 의견 작성 부담 | 개인 공간이 이해·표현에 도움이 됐는지 설문·면담 |
| 업무 이해 | 목적·범위·결과물·기한을 팀원들이 같은 기준으로 이해하는지 확인 |
| 업무 조율 | 누락 조건 확인과 재설명·수정 부담을 관찰 |
| AI 정확성 | 카드·설명·기록 요약을 원문과 등록 자료에 대조 |

가능한 범위에서 비슷한 난이도의 다른 과제를 사용하고 순서를 교차해 반복 사용의 영향을 줄입니다. 모집된 실제 인원·언어·사용 시간, 유리하거나 불리했던 사례를 함께 보고합니다. 소규모 관찰 결과는 초기 사용성과 개선점을 찾는 근거로 해석합니다.

## 7. 권한·승인·실패 상황

- 다른 팀·다른 계정에서 개인 AI 대화와 초안에 접근할 수 없는지 점검합니다.
- 공유 버튼을 누르기 전 개인 내용이 팀 채팅이나 공통 요약에 포함되지 않는지 확인합니다.
- AI 오류·지연에도 기본 채팅을 이어갈 수 있도록 설계합니다.
- 명시적인 확인 없이 결정·업무 배정이 최종 상태로 바뀌지 않는지 점검합니다.
- 미응답·알림 건너뛰기를 동의나 불성실로 해석하지 않습니다.
- 실제 대화는 안내와 동의 범위에서 활용하고, 공개 시연에는 가상 대화를 사용합니다.

## 8. 이후 기록할 결과

개발이 진행되면 구현된 기능과 제한, 실제 API 구성·응답시간·비용, 테스트 조건과 실패 사례, 파일럿 피드백, 수정 내역을 추가합니다. 이후 3~5개 팀 시범 운영이나 지원 언어 확대는 초기 검증 이후에 판단할 계획입니다.
