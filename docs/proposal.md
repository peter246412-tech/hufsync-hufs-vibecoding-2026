# HUFSync 기획안 정리

사용자가 제공한 2026년 11월 10일자 대회 기획안을 바탕으로 구성한 공개용 문서입니다. [기획서 PDF 공개본](submission/hufsync-proposal-public.pdf)에는 본문을 보존했고, 이 문서는 읽기 쉬운 순서로 요점을 정리했습니다. 아래 기능·효과·검증은 기획 및 계획 단계입니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | HUFSync · 훕싱크 |
| 팀 | 알파메일 · 한국외대 Social Science & AI 4인 팀 |
| 대회 맥락 | 2026 한국외대 AI 캠퍼스: 바이브코딩 경진대회 지원 기획 |
| 대상 사용자 | 내·외국인 학생이 함께 참여하는 소규모 팀 프로젝트 |
| 초기 언어 | 한국어·영어·중국어 |
| 목표 결과물 | 모바일·PC 브라우저에서 사용하는 웹 기반 MVP |

HUFSync는 다국어 대화에서 현재의 논의를 정리하고, 학생이 자신의 언어로 의견을 준비하도록 돕고, 팀이 정한 내용을 업무와 결과물까지 연결하는 AI 협업 조정 플랫폼입니다.

## 2. 기획 배경

### 함께 수행했지만 충분히 함께 논의하지 못한 경험

중국인 유학생과 진행한 팀 프로젝트에서 빠른 한국어 대화와 전공 용어는 참여에 부담이 됐습니다. 설명을 요청하는 사람과 반복해 전달하는 사람 모두에게 부담이 쌓이면서, 서로를 배려하려 독립적인 자료 조사 업무를 나누게 됐습니다.

이후 조사 범위·결과물 형식·활용 목적을 충분히 확인하지 못한 차이가 취합 단계에서 드러났습니다. 기획안은 이를 특정 학생의 성실성 문제가 아니라, 함께 논의하고 같은 작업 기준을 확인할 기회가 부족했던 경험으로 해석합니다.

### 다국어 팀플에서 연결할 두 가지 지원

1. **논의 참여:** 현재 무엇을 정하고 있는지 이해하고, 질문하거나 자기 의견을 표현할 수 있는 환경.
2. **업무 이해:** 담당 업무의 목적·수행 범위·결과물·기한을 확인하고, 진행 상황과 결과물을 공유할 수 있는 환경.

한국외대 공식 학교 현황에는 2025년 4월 1일 기준 서울캠퍼스 학부 재학생 9,823명, 외국인 학부 학위과정 학생 2,108명이 제시되어 있습니다. 같은 범위에서 계산한 비율은 약 21.5%입니다. 학위·연수과정을 섞은 대학별 순위 대신 이처럼 범위를 맞춘 교내 현황을 근거로 사용합니다. [공식 학교 현황](https://stat.hufs.ac.kr/hufs/11142/subview.do)

서윤경·김수영(2026)의 질적 연구는 배려에 따른 참여 제한과 공통된 협업 이해 부족 등을 다룹니다. Do et al.(2022)의 그룹 채팅 연구는 비공개 개인 지원과 공개 방식의 사용자 경험 차이를 살펴보는 설계 근거로 참고했습니다. 연구가 HUFSync의 효과를 직접 검증한 것은 아니므로 실제 효과는 별도 파일럿에서 확인할 계획입니다. [연구별 확인 범위](references.md)

## 3. 서비스의 네 가지 핵심 영역

### AI 토론 흐름 카드

채팅 상단에 현재 주제, 주요 제안, 미해결 질문, 결정 상태를 표시합니다. 각 항목에는 실제 근거 메시지를 연결하고, 사용자가 선호 언어로 확인하도록 설계합니다.

질문에는 고유 ID를 부여해 관련 의견과 결정 내용을 이어갑니다. 질문 상태는 ‘답변 필요 → 검토 중 → 해결됨’으로 관리하고, 해결 여부와 최종 결정은 팀원이 확인합니다.

### 비공개 AI 조정자

학생이 메시지·질문·업무를 선택하면 자신의 언어로 맥락을 설명받고 추가 질문을 할 수 있습니다. 개인 공간에서 의견을 작성하고 번역문을 미리 확인한 뒤 직접 공유합니다.

새로운 주제나 미해결 질문이 등록되면 알림을 허용한 사용자에게 비공개 안내를 제공합니다. 개인별 발언 점수로 대상을 선정하는 대신, 논의에서 발생한 사건을 기준으로 안내합니다. 중복 알림을 제한하고 건너뛰기·알림 끄기를 제공합니다.

### AI Task Alignment

채팅 속 업무 요청을 이전 결정과 연결해 업무 카드 초안으로 정리합니다. 업무명, 목적, 담당자, 수행 범위, 결과물, 기한을 추출하고 불명확한 항목은 ‘확인 필요’로 남깁니다.

예를 들어 ‘중국 기업을 조사해 줘’라는 요청에 앞서 확정한 BYD·Tesla 비교와 비교 기준을 연결합니다. 담당자와 결과물 형식, 기한은 팀원이 확인한 뒤 확정하도록 합니다.

### 협업 진행 및 Contribution 기록

확정된 업무를 ‘할 일 → 진행 중 → 검토 요청 → 완료’로 관리합니다. 자료와 결과물 링크, 검토 상태, 공동 결과물에 반영된 내역을 업무에 연결합니다.

Contribution은 등록된 작업과 팀이 확인한 반영 내역을 요약하는 기능으로 구상했습니다. AI가 관찰하지 못한 작업이나 개인의 전체 기여도를 추정해 점수화하지 않습니다.

## 4. 사용 흐름

**팀 채팅 → 논의 상황 확인 → 비공개 의견 준비 → 팀 공유·결정 → 업무 카드 초안 → 조건 확인·확정 → 작업·검토·결과물 기록**

| 단계 | 사용자와 시스템의 역할 |
| --- | --- |
| 대화 | 팀원들이 각자의 언어로 메시지를 작성 |
| 분석 | AI가 주제·의견·질문·결정 후보와 근거를 추출 |
| 개인 지원 | 사용자가 맥락을 질문하고 모국어로 초안을 준비 |
| 의견 공유 | 본인이 번역문을 확인하고 공유 승인 |
| 결정 | 팀원이 질문 상태와 선택 이유를 확인해 기록 |
| 업무 정렬 | AI가 이전 결정을 연결하고 누락된 업무 조건을 표시 |
| 업무 확정 | 팀원이 담당자·범위·결과물·기한 검토 |
| 공동작업 | 진행 상태·결과물·수정 요청·반영 내역을 기록 |

[대표 시나리오](user-scenario.md)에서 전체 과정을 가상 대화로 설명합니다.

## 5. 기존 방식과의 차별화 방향

Slack 등 기존 협업 도구에도 번역과 요약 기능이 있습니다. HUFSync는 한국인과 외국인 대학생의 팀플에서 **공통 논의 맥락, 비공개 의견 준비, 업무 기준 확인**을 연속된 흐름으로 연결하는 방향을 택했습니다.

- 단어의 뜻을 이해한 뒤 현재 질문에 자기 의견을 연결할 수 있도록 합니다.
- 업무를 등록할 때 앞서 결정한 기준과 누락된 조건을 함께 확인합니다.
- 의견이 실제 업무와 공동 결과물에 어떻게 이어졌는지 기록합니다.

개별 기능의 최초 개발보다 대상 사용자에게 맞는 연결 과정의 유용성을 검증하고자 합니다.

## 6. AI·바이브코딩 활용 계획

개발에는 Cursor/Codex, ChatGPT·Claude 등을 활용해 화면과 데이터 흐름을 명세하고 코드를 생성·수정할 계획입니다. 팀원들이 직접 접근 권한, 예외 처리, 다국어 표시와 주요 흐름을 확인합니다.

서비스는 Next.js, Supabase, 생성형 AI API, Vercel을 검토합니다. HyperCLOVA X를 우선 후보로 두고 이용 가능 여부, 한·영·중 처리 성능과 비용을 확인해 단일 AI API 중심으로 초기 MVP를 구현할 계획입니다.

프롬프트는 대화 분석, 비공개 설명·의견 준비, 업무 요청 추출, 작업 기록 요약으로 구분합니다. 예시 입력과 기대 출력을 이용해 조정하며, 원문에 없는 결정이나 업무 조건을 생성하는지 검증합니다.

[아키텍처 설계](architecture.md)에는 모듈·데이터·권한·오류 처리의 구체적인 검토안을 정리했습니다.

## 7. 구현·검증 계획 및 기대효과

본선 진출 시 공식 개발 기간인 2026년 11월 16일~12월 6일의 3주 동안 핵심 흐름을 구현하는 계획입니다. 가상 한·영·중 대화로 정보 추출과 상태 연결을 점검하고, 내·외국인 혼합 1~2개 팀·약 4~8명 파일럿을 목표로 합니다.

확인할 내용은 토론 이해 정확성, 의견 작성 부담, 업무 이해 정확성, 업무 조율 부담, AI 정리의 근거 일치입니다. 소규모 검증에서 서비스의 초기 사용성과 개선점을 파악하고자 합니다.

기대효과는 의견 전달 기회 확대, 반복적인 맥락 설명 부담 감소, 작업 기준 차이로 인한 재작업 완화입니다. 이후 3~5개 팀 시범 운영과 지원 언어 확대를 검토하되, 실제 모집·운영·성과는 진행된 범위에서 따로 기록합니다.
